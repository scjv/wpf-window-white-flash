# Светлая вспышка при открытии тёмного окна WPF

[English](README.md) · Русский

Окно WPF на .NET 10 в тёмной теме Fluent несколько кадров показывает светлый прямоугольник, прежде чем
появится его тёмное содержимое. Здесь собраны минимальный репро, исправление и измерения, на которых они
основаны: каждый кадр, собранный DWM за 521 запуск окна, записанный через DXGI Desktop Duplication.

**Коротко**

- **Причина.** С момента `ShowWindow` и до того, как поток рендеринга WPF выведет (present) первый кадр
  окна, DWM рисует окно по его незакрашенной поверхности, а она белая. Анимация открытия Windows 11
  проявляет её постепенно, поэтому это выглядит как бледная вспышка. Тема ни при чём: обычная тёмная
  `SolidColorBrush`, фон Mica и программный рендеринг вспыхивают точно так же.
- **Почему первый кадр опаздывает.** Активированное окно тратит около 40 мс UI-потока на активацию внутри
  `ShowWindow`, и его первый кадр приходит через 60–110 мс после того, как окно стало видимым, — намного
  позже, чем DWM начал его рисовать. Окно, открытое *без* активации, получает первый кадр примерно через
  12 мс, раньше, чем его нарисует DWM, и не вспыхивает.
- **Исправление.** Скрыть окно через `DWMWA_CLOAK`, когда оно активируется при открытии, и раскрыть, как
  только первый кадр выведен: в `ContentRendered`, после внутреннего метода WPF
  `MediaContext.CompleteRender`. Окно, которое открывается без активации, не трогать:
  [FirstFrameCloak.cs](FirstFrameCloak.cs). С исправлением — ни одной вспышки за 50 запусков (с активацией
  и без, программный рендеринг, Mica, тяжёлый первый кадр), без него — вспышка в 10 из 10.
- **Не раньше.** Если раскрыть окно в `Loaded`, на `WM_ERASEBKGND` или на первом тике
  `CompositionTarget.Rendering`, видна белая поверхность; то же, если скрывать окно, которое открывается
  без активации. Раскрытие в `ContentRendered` без ожидания present почти достаточно: оно не сработало
  в 1 из 6 запусков на занятом компьютере и всегда — с тяжёлым первым кадром.

## Исправление

```csharp
// SourceInitialized: подключаем обработчик оконной процедуры. Активация приходит внутри ShowWindow, сразу
// после того, как окно стало видимым, и до того, как его нарисовал DWM.
if (!cloaked && msg is WM_NCACTIVATE or WM_ACTIVATE && wParam != IntPtr.Zero && IsWindowVisible(hwnd))
{
    cloaked = true;
    SetCloaked(hwnd, true);             // DwmSetWindowAttribute(hwnd, DWMWA_CLOAK = 13, TRUE)
}

// ContentRendered: UI-поток передал первый кадр потоку рендеринга. Ждём, пока тот его выведет
// (внутренний MediaContext.CompleteRender через reflection), и показываем окно.
if (cloaked)
{
    CompleteRender?.Invoke(window.Dispatcher);
    SetCloaked(hwnd, false);
}
```

Полный класс — [FirstFrameCloak.cs](FirstFrameCloak.cs); подключите его к окну до того, как окно будет
показано. Скрытое окно остаётся видимым для Win32 (`WS_VISIBLE`), и WPF рисует в него как обычно; DWM
просто его не выводит. После раскрытия окно появляется сразу с тёмным содержимым, без анимации открытия
Windows 11.

- **Зачем ждать present?** `ContentRendered` срабатывает, когда UI-поток передал первый кадр потоку
  рендеринга. Обычно к этому моменту кадр уже на экране, но не всегда: в контрольной серии 1 из 6
  запусков, раскрывавших окно прямо там, около 30 мс показывал белое (в это время за компьютером
  работали), а кадр, дорогой в отрисовке (`heavy`), показывал белое каждый раз. Публичного API, который
  ждёт present, в WPF нет. `MediaContext.CompleteRender` — внутренний метод; WPF сам вызывает его при
  изменении размера окна, и в его комментарии сказано, что он «will only return after the last frame is
  presented». `FirstFrameCloak` находит его через reflection, а если в будущей версии WPF его не окажется,
  раскрывает окно без ожидания.
- **Почему только активированные окна?** Окно, которое открывается без активации (трей-приложение
  открывает окно, пока пользователь работает в другом), выводит первый кадр примерно через 12 мс после
  появления, раньше, чем его нарисует DWM: оно не вспыхивает, и скрывать его не нужно. Скрытие здесь только
  добавляет риск: окно, показанное скрытым, DWM после раскрытия рисует сразу, без короткой паузы, которую он
  даёт только что показанному окну. Поэтому раскрытие такого окна в `ContentRendered` дало белый кадр
  (`noactivate+cloak=cr`, 1 из 6).
- **Нужно только при первом показе.** Если скрыть окно (`Hide`) и показать снова, вспышки нет: DWM
  сохраняет уже отрисованную поверхность.

## Что происходит при запуске

Типичный запуск репро по журналу событий FlashLab и записанным кадрам (миллисекунды от момента, когда окно
стало `WS_VISIBLE`):

| мс | Окно с активацией | Окно без активации |
| ---: | --- | --- |
| −110 | `SourceInitialized`; WPF уже выставил `DWMWA_USE_IMMERSIVE_DARK_MODE`, поэтому заголовок тёмный с первого кадра | так же |
| −110…0 | `WM_SHOWWINDOW`: UI-поток ждёт, пока поток рендеринга подготовит Direct3D для окна (при программном рендеринге — мгновенно) | так же |
| 0 | Окно становится видимым | так же |
| ~5 | `WM_NCACTIVATE` / `WM_ACTIVATE`: работа активации (фокус, текстовые службы, …) занимает UI-поток примерно на 40 мс | — |
| ~5 | | Первая раскладка (`Loaded`) |
| ~12 | | Первый кадр отрисован (`ContentRendered`) и выведен |
| 10–30 | DWM начинает рисовать окно: незакрашенная белая поверхность проявляется вместе с анимацией открытия | DWM начинает рисовать окно: первый кадр уже есть, тёмный |
| ~45 | Первая раскладка (`Loaded`), всё ещё внутри `Window.Show()` | |
| 60–110 | Первый кадр выведен (`ContentRendered`); тёмное содержимое сменяет белую поверхность | |

Почему поверхность не тёмная: WPF регистрирует класс окна с `NULL_BRUSH` и отвечает на `WM_ERASEBKGND`,
ничего не рисуя, поэтому до вывода кадра потоком рендеринга в окне ничего нет. С отключённой анимацией
открытия (`DWMWA_TRANSITIONS_FORCEDISABLED`) клиентская область около 45 мс чисто белая (luma 255).

## Как измерялось

[`FlashProbe`](FlashProbe) запускает приложение, забирает каждый кадр, который собирает DWM
(`IDXGIOutputDuplication::AcquireNextFrame` на каждом мониторе), и измеряет среднюю яркость (luma по
Rec. 709, 0–255) клиентской области и заголовка окна там, где окно находится. Последний кадр перед
появлением окна показывает, что за ним; с `--backdrop` это однотонное серое окно (luma 64), чтобы числа не
зависели от рабочего стола.

- **Кадр вспышки:** клиентская область более чем на 8 ярче и того, что за окном, и готового окна. Пока
  окно проявляется, оно — смесь этих двух; всё, что ярче, может дать только светлая поверхность.
- **Показано:** первый кадр, который отличается от того, что за окном. **Не показано:** окно не появилось
  за 1,5 с записи.
- **Закрыто:** поверх центра окна лежит другое окно. Такие кадры показывают то окно, поэтому они
  исключаются, а `Run-Experiments.ps1` считает такие запуски отдельно (см.
  [ловушку измерения](#ловушка-измерения-кто-то-работает-за-компьютером)).
- FlashLab пишет свои шаги (`Loaded`, `ContentRendered`, `Uncloaked`, …) в stdout с метками времени
  `Stopwatch`; утилита кладёт их на ту же шкалу времени.

Тестовая машина ([environment.txt](results/final-fix/environment.txt)): Windows 11 Home 10.0.26200;
.NET SDK 10.0.401 с рантаймом WindowsDesktop 10.0.12; окно открывалось на мониторе 3840×2160, 60 Гц,
масштаб 150 %, подключённом к NVIDIA GeForce RTX 4060 Laptop GPU (экран ноутбука работает от AMD Radeon
780M); анимации окон включены, тёмная тема приложений.

## Что не работает

- **Другая настройка темы.** `plain` (без `ThemeMode`, тёмная `SolidColorBrush`), `mica` (включён фон Mica
  из Fluent) и `software` (программный рендеринг) вспыхивают так же, как репро.
- **Заливка фона в `WM_ERASEBKGND`** (`erase`). WPF получает это сообщение примерно через 40 мс после
  появления окна, когда DWM уже показывает белую поверхность, и GDI-заливка её не заменяет.
- **Рендеринг пораньше** (`sync`). `Window.Show()` делает первую раскладку уже после `ShowWindow`, поэтому
  первый кадр нельзя вывести раньше, чем на экране окажется белая поверхность.
- **Отключение текстовых служб для окна** (`noime`). Первый кадр приходит примерно на 30 мс раньше, но
  вспышка остаётся.
- **Отключение анимации открытия** (`nofade`). Хуже: белая поверхность показывается в полную силу.
- **Раскрытие до первого present**: в `Loaded`, на первом `WM_ERASEBKGND` (оба варианта предлагали
  в [dotnet/wpf#5853](https://github.com/dotnet/wpf/issues/5853)) или на первом тике
  `CompositionTarget.Rendering` (`cloak=loaded`, `cloak=erase`, `cloak=tick`). DWM сразу показывает белую
  поверхность, без проявления. Раскрытие сразу после первой операции рендеринга (`cloak=opdone`) —
  на грани.
- **Скрытие окна, которое открывается без активации**, с раскрытием в `ContentRendered`, в `Loaded` или
  внутри `ShowWindow` (`noactivate+cloak=cr`, `cloak=active`, `cloak=showpos`): белый кадр там, где то же
  окно без скрытия не вспыхивает.
- **Скрытие только после показа окна** (`onshow`, на `WM_WINDOWPOSCHANGED` с `SWP_SHOWWINDOW`). Для
  активированного окна поздно: это сообщение приходит после работы активации, когда DWM уже нарисовал окно.
- **Пустой регион окна вместо скрытия** (`rgn`). Сброс региона возвращает белый кадр.

## Ловушка измерения: кто-то работает за компьютером

В 8 исследовательских сериях окно переставало появляться на записях: не было видно даже заголовка. Это
всегда начиналось посреди серии, после 7–19 запусков, и затем затрагивало все оставшиеся запуски этой
серии (всего 40); первый кадр у этих запусков к тому же приходил рано (`ContentRendered` через 28–62 мс
после появления окна вместо 60–110 мс). Так вышло, что это были варианты с поздним раскрытием, и поначалу
это выглядело как проблема WPF или DWM с выводом кадров в скрытое окно.

Скорее всего, это артефакт записи. Пока кто-то работает за компьютером, Windows не даёт фоновому процессу
выйти на передний план
([блокировка переднего плана](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-setforegroundwindow)),
поэтому новое окно открывается без полной активации — это же объясняет ранний первый кадр — и может
оказаться под окном, с которым работают, вне поля зрения записи. В контрольной серии был один такой запуск
(`cloak=cr+onshow`): его окно было активировано, но к `ContentRendered` уже не было на переднем плане,
серая подложка тоже была закрыта, и окно так и не появилось в кадрах. У вариантов с поздним раскрытием
в контрольной серии таких запусков не было.

Поэтому FlashProbe для каждого кадра проверяет, не закрывает ли центр окна другое окно (`WindowFromPoint`),
исключает такие кадры из метрик и сообщает о них (`covered_frames`); `Run-Experiments.ps1` считает такие
запуски отдельно. Исследовательские запуски записаны до этой проверки; «не показанные» среди них — это
строки с пустым `shown_ms` в [`results/exploratory-runs.csv`](results/exploratory-runs.csv).

## Ограничения

- Ожидание present опирается на внутренний метод WPF. Без него (если будущая версия WPF его уберёт)
  `FirstFrameCloak` раскрывает окно в `ContentRendered` сразу; как это работает, показывают строки
  с пометкой «ранний» выше.
- Окно появляется, только когда его первый кадр уже на экране: с тяжёлым первым кадром (`heavy`, около
  0,9 с) оно появляется настолько же позже — зато тёмным, а не белым.
- Одна машина (см. выше). Тайминги зависят от видеокарты, драйвера, частоты обновления и нагрузки; от них
  же зависит, успеет ли окно без активации раньше DWM.
- Активированное окно теряет анимацию открытия Windows 11.

## Как воспроизвести

```powershell
pwsh ./Run-Experiments.ps1 -Runs 6 -Name my-run     # все режимы по умолчанию, около 14 минут
pwsh ./Run-Experiments.ps1 -Runs 10 -Name my-fix-check -Modes minimal+no-cloak,minimal,minimal+no-activate,software+cloak=complete+onactivate,mica+cloak=complete+onactivate,cloak=complete+onactivate+heavy
```

Окна открываются посреди основного монитора поверх серой подложки; пока скрипт работает, не трогайте
компьютер. Он печатает строку на каждый запуск и таблицу по режимам и пишет `results/<name>/`
(`summary.csv`, `aggregate.csv`, `environment.txt`; файлы кадров и событий по запускам в `runs/` в git не
попадают). Режимы, начинающиеся с `minimal`, запускают репро, и каждый `+flag` превращается в `--flag`
(`minimal+no-activate+no-cloak`); все остальные режимы запускают FlashLab. Один запуск вручную:

```powershell
FlashProbe/bin/Release/net10.0-windows/FlashProbe.exe FlashLab/bin/Release/net10.0-windows10.0.19041.0/FlashLab.exe `
    --args "cloak=cr" --backdrop --save 300 --verbose --out probe-output
```

`--save <ms>` сохраняет в PNG каждый кадр первых миллисекунд записи; `--snapshot` сохраняет весь экран
в конце записи (полезно, когда окно так и не появилось).

### Режимы FlashLab

Режим — это список флагов через `+`, например `software+cloak=cr` или `cloak=frames+inval`. Без флагов
(`baseline`) FlashLab — это репро без исправления.

| Флаг | Действие |
| --- | --- |
| `plain` | Без `ThemeMode`; фон окна — `SolidColorBrush` цвета `#202020` |
| `mica` | Снова включает фон Mica из Fluent (в csproj он отключён, как в приложении, из которого взят репро) |
| `software` | `RenderOptions.ProcessRenderMode = SoftwareOnly` |
| `noactivate` | `ShowActivated = false`: окно открывается без активации |
| `noime` | `InputMethod.IsInputMethodEnabled = false` для окна |
| `heavy` | Добавляет элемент, первый кадр которого занимает у потока рендеринга около 0,9 с |
| `erase` | Заливает клиентскую область цветом `#202020` на `WM_ERASEBKGND` |
| `nofade` | `DWMWA_TRANSITIONS_FORCEDISABLED`: без анимации открытия |
| `sync` | `Show()`, затем синхронные раскладка и рендеринг до `Application.Run` |
| `forcefast` | В `Loaded`: отрисовать и дождаться present (`MediaContext.CompleteRender` через reflection) |
| `delayrender` | В `Loaded`: пауза 300 мс, первый кадр задерживается |
| `reshow` | Скрыть окно через 600 мс после первого кадра и снова показать ещё через 600 мс |
| `cloak=<when>` | `DWMWA_CLOAK` в `SourceInitialized`, раскрытие в момент `<when>`: `loaded`; `erase` (первый `WM_ERASEBKGND`); `tick` (первый `CompositionTarget.Rendering`); `opdone` (сразу после первой операции рендеринга); `cr` (`ContentRendered`); `active` (в `Loaded`, если окно не активно, иначе `ContentRendered`); `showpos` (внутри `ShowWindow`, если окно не стало активным, иначе `ContentRendered`); `frames` (три тика `Rendering` после `ContentRendered`); `frames-post` (то же, затем отложенный вызов через диспетчер с приоритетом `Background`); `complete` (после `MediaContext.CompleteRender`); `late` (через 300 мс после `ContentRendered`) |
| `onactivate` | Вместе с `cloak=`: скрытие на первом `WM_NCACTIVATE`/`WM_ACTIVATE` вместо `SourceInitialized`. `cloak=complete+onactivate` — это то, что делает `FirstFrameCloak` |
| `onshow` | Вместе с `cloak=`: скрытие на `WM_WINDOWPOSCHANGED` с `SWP_SHOWWINDOW` вместо `SourceInitialized` |
| `rgn` | Вместе с `cloak=`: скрывать пустым регионом окна (`SetWindowRgn`) вместо `DWMWA_CLOAK` |
| `inval`, `rm`, `framechanged` | После раскрытия: `InvalidateRect`; переключить `HwndTarget.RenderMode` на программный рендеринг и обратно; `SWP_FRAMECHANGED` |
